# Racing expansion handoff

Start with `npm start`, open `http://localhost:3000`, scan the QR from phones on the same LAN. HTTPS/gyro setup is linked beside the QR. Each joined phone is a controller; the common monitor renders all views. The first joined driver is HOST, including when that driver is a phone. Everyone chooses a car and primary body paint, then taps Ready. HOST chooses circuit, mode and 1–20 laps, then Start. Setup changes reset readiness. Opening a display tab never grants host-player powers.

Twenty-four new hand-authored centerlines are registered in `public/track-catalog.js`, three per class theme. Original Coastal remains, for 25 total. The track atlas at `/tracks` shows maps, metadata and actual 3D scenery. Every track accepts all eight cars. Physics and rendering share arc-length samples, elevation, banking and ordered checkpoints. There are park/city/forest/mountain/dock/canyon/stadium/glass/runway/desert/expressway/alpine/coast/valley environments, bridge sections, tunnel sections and night palettes. Class themes do not lock cars or secretly alter their stats. Rainline is explicitly a dry overcast circuit; no wet tire model is implied.

Modes: Circuit Race uses ordered laps and fills empty grid seats with bots. Time Trial disables car collisions and ranks best valid lap. Drift Challenge runs for 120 seconds and scores speed × controlled slip angle × clean-drift combo; dirty/offroad/contact resets the combo. Barriers, drafting, slope/banking and car-specific aero grip are shared across all tracks. This remains an arcade simulation, not a licensed F1 simulator.

Exactly 16 named body paints are registered in `public/race-rules.js`. Only the primary white material is cloned and recolored per car; the original red/black trim, wheel accents, glass and lights stay intact. Lobby previews render the actual selected car and paint. Models retain editable native Three.js source and rebuilt GLB exports.

Shared display: one driver = full viewport; two = equal top/bottom; three = equal left/middle/right columns; four = top-left, top-right, bottom-left, bottom-right in join order. Independent camera aspect ratios and HUDs follow identities. A disconnected racer becomes AI for the remainder of that race, keeping the other cameras stable; a valid reconnect restores the same car and inputs. Lobby leave immediately rebuilds slots. Host authority transfers to the earliest remaining participant. Empty rooms reset their race settings.

Keyboard: WASD/arrows, Shift drift, B/Space ERS, R rescue. Text/select controls do not steal driving shortcuts. Gamepad: A join/ready; LB/RB car; D-pad left/right paint; host Y next track, X next mode, D-pad up/down laps, Start race; RT throttle, LT brake, B drift, X ERS, Y rescue; Back leave; host Start returns from results. Gamepad support uses separate websocket identities per device. Hardware behavior is not physically verified.

Phone: landscape F1 wheel with original gyro orientation handling, independent pedals, drift hold/toggle and ERS. Lobby / Ready opens setup and personal audio. On unsupported orientation-lock browsers, the controller rotates its layout in portrait. Losing focus, stale gyro, disconnect and hidden tabs release inputs. Native fullscreen on the TV requires a click on that TV's page; a phone host's Start still fills the TV browser window through CSS, but browsers do not permit a remote phone to force another device into native fullscreen.

Validation: `npm test` exercises the server, physics, all eight models, all 16 paints, input ownership, host transfer, resume tokens, audio provenance/mixing and exact 1920×1080 layout math. `npm run tracks:validate` physically simulates every car for one ordered lap on all 25 tracks (200 total, 192 new pairings), checks finite geometry, spawns/rescue, grades and road clearance, and writes `docs/track-validation.json`. `npm run tracks:build`, `npm run assets:build`, `npm run audio:build` reproduce maps, GLBs and original audio. There is no separate bundler or lint configuration in this project.

Browser evidence is under `docs/screenshots/`. These are actual connected players and renderer output. Audio notes and source credits are in `docs/PERSONAL_AUDIO.md` and `AUDIO_SOURCES.md`. Physical gyro, speakers, phones, gamepads, and exhaustive manual driving of all 192 combinations remain unverified; the compatibility matrix is an automated driving simulation.
